# TRIAS website
Independent static marketing and downloads site. No npm dependencies, Unity build, backend or secrets.

## Vercel
Import iLoopak/trias-fps as a new Vercel project. Set Root Directory to website, Framework Preset to Other, Output Directory to public. No install or build command is needed. Configuration is included in vercel.json. Deploy the PR branch as a preview or main after merging. The existing game server is not deployed by this project.

## Local preview
From repository root: `python -m http.server 8080 --directory website/public`. Open http://localhost:8080.

## Publish a game build
1. Build the desired Unity platform using the existing game build process. Package the complete player output, not just its executable (e.g. Windows EXE, Data directory and required DLLs).
2. Create a GitHub Release with a version tag, e.g. v0.1.0-alpha.1. Mark unstable builds as prereleases.
3. Upload game archives/installers as release assets, e.g. TRIAS-windows-x64.zip. Add installation instructions, known issues, and compatible server version/address to the release notes. Do not commit binary packages to the website.
4. Publish the release. The downloads section discovers the newest published release containing supported uploaded packages (including prereleases), using the public GitHub API. No Vercel redeploy is needed. The page links to the archive for older versions. GitHub rate limiting or network errors use a visible fallback link. Source archives generated by GitHub are not listed as game builds.
5. Optional later: automate packaging and release asset upload in GitHub Actions after platform builds have been validated.

This is not a hosted multiplayer server. The existing Node.js WebSocket server needs separate persistent hosting or a local instance. Offline/online capabilities depend on the packaged build.
